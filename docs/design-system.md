# 디자인 시스템

## 목적과 현재 상태

일관되고 접근하기 쉬운 UI를 재사용할 수 있도록 디자인 기준을 관리한다. 시작 화면과 대국 UI는 `src/design-system/tokens.css`의 색상, 간격, 포커스와 조작 영역 토큰을 공유한다. 오목판은 따뜻한 목색 바탕과 짙은 격자에 흑·백돌을 표시하고, 주변 조작에는 기존 녹색을 사용한다.

> 2026-11-06 기준: 아래 버튼·내비게이션 구현은 로컬 작업 중이며 아직 GitHub에 반영되지 않았다. 원격 코드와 동기화한 뒤 사용한다.

## 공통 컴포넌트 사용법

- `<Button onClick={handleClick}>디자인 미리보기</Button>`은 주요 동작에 사용한다. 보조 동작에는 `variant="secondary"`를, 실행할 수 없는 동작에는 `disabled`를 지정한다. 기본 타입은 `button`이며 폼을 제출할 때는 `type="submit"`을 명시한다.
- `<MenuNavigation label="주 내비게이션" items={[{ href: '#welcome', label: '시작 화면' }]} />`처럼 실제 목적지가 있는 링크를 전달한다. Tab으로 링크 사이를 이동하고, Esc를 누르면 메뉴가 닫히며 메뉴 버튼으로 포커스가 돌아온다.
- 시작 화면의 **디자인 미리보기**를 열면 기본 버튼의 마우스 오버·키보드 포커스와 비활성 예시를 확인할 수 있다.

## 대국 UI 사용법

- `GomokuBoard`에 좌표별 `cells`와 선택 가능 여부를 반환하는 `isSelectable(point)`, 선택을 전달하는 `onSelect(point)`를 넘긴다. 좌표는 0부터 시작하는 행·열이며, `boardCoordinate(point)`로 `H8` 형식의 키를 만든다. 셀은 흑·백돌, 최근 착수, 승리 줄과 공개 효과 표식을 받는다. `walls`는 공개된 선분만 받는다. 읽기 전용 판은 `onSelect`를 생략한다.
- 판은 Tab으로 들어간 뒤 방향키, Home·End로 이동한다. Enter·Space로 교차점을 선택한다. 모바일의 **판 확대**를 켜면 넓어진 교차점을 스크롤하며 조작할 수 있다. 미리보기에서는 선택과 확정을 분리해 좌표를 확인할 수 있다.
- `Modal`은 제목과 설명, 본문, 동작 버튼을 받는다. 브라우저의 모달 포커스 관리를 사용하며, Esc로 닫은 뒤 호출 버튼으로 돌아간다. 여러 후보 중 하나를 고르는 경우 `GameChoiceModal`을 사용한다. 인라인 선택에는 `GameChoices`를 사용한다. 선택 불가 후보는 `unavailable`에 이유를 넣는다.
- `PlayerStatus`에 돌 색, 현재 턴과 개인별 목표를 넘긴다. `SkillHand`에 화면에서 볼 수 있는 카드와 상세 열기 콜백을 전달한다. `GameNotice`는 진행·경고·오류 메시지를 텍스트로 안내하며 즉시 읽어야 하는 오류에는 `alert`를 지정한다.

시작 화면의 **대국 미리보기**에서 5목·6목 설정, 착수와 카드 대상 선택, 증강 3택 1, 방어·건너뛰기, 승리·무승부, 방 참가·대기·재연결·실패를 확인할 수 있다. 룰북에는 기획서의 공격·방어 카드 21종과 증강 10종을 실었다. 예시 데이터와 화면 조작은 `src/game-preview`에 모았다.

개발 연동 시 규칙·세션에서 받은 합법 좌표, 턴·라운드, 개인 목표, 카드 사용 가능 사유, 증강 후보, 응답 요청, 승리 줄과 연결 상태를 UI에 매핑한다. 착수·카드·응답 확정은 명령으로 보낸다. 상대에게 보이지 않는 손패·지뢰·은신 정보는 서버에서 걸러낸 뒤 공개 뷰만 전달한다. 방어 타이밍·제한 시간, 증강 지급 시점, 버프·특수 카드와 조우자의 효과는 기획이 확정되면 연결한다.

## 작업 경계

- 디자인 채팅: 시각 방향, 토큰, 공통 UI 컴포넌트 및 상태, 접근성, 사용법을 관리한다.
- 개발 채팅: 게임 규칙과 데이터, 온라인 상태를 UI에 연결하고 실제 기능을 검증한다.
- 공통 컴포넌트를 바꾸면 사용법과 영향을 받는 화면을 함께 확인한다. 컴포넌트에 게임 규칙이나 통신을 직접 결합하지 않는다.

## 설계 시 확인할 항목

키보드 조작과 포커스, 명도 대비, 색상 외 상태 표시, 모바일 터치 영역, 반응형 레이아웃, 모션 감소 설정, 로딩·오류·연결 상태를 고려한다. 구체적인 색상·타이포그래피·컴포넌트 규격은 디자인이 정해지면 이 문서와 실제 코드에 반영한다.
