# 개발 가이드와 채팅 전달

기획 기준은 [game-spec.md](game-spec.md), 공통 UI는 [design-system.md](design-system.md)를 확인한다. 단계는 의존 순서이며 기획 변경에 따라 조정한다. 완료되지 않은 규칙을 기능으로 확정하지 않는다.

## 공통 설계

- React 화면과 독립된 TypeScript 게임 규칙을 중심으로 상태·행동·검증·결과를 분리한다. UI는 상태를 표시하고 명령을 전달한다.
- 판, 플레이어, 턴, 라운드, 돌, 카드와 승리 조건을 명시적으로 모델링한다. 현재 구현과 검증은 2인 대국을 기준으로 한다. 플레이어 ID와 순서 목록을 중심으로 모델링해 향후 3인 대국을 검토할 수 있게 한다.
- 공격에 대한 턴 밖 방어와 즉시·지속·지연·숨김 효과를 지원해야 한다. 행동 가능 시점, 응답 대기, 효과 순서와 종료 처리는 기획 확정 후 모델에 반영한다.
- 무작위 선택은 규칙 계산에서 제어 가능하게 분리해 같은 입력과 난수 조건을 재현할 수 있도록 한다.
- 온라인 기능은 통신 인터페이스와 규칙을 분리한다. 숨긴 카드·지뢰·은신 정보는 상대 클라이언트로 전달하지 않는 구조를 검토하고, 턴 검증과 비밀 정보 보호에 필요한 신뢰 가능한 백엔드를 기획에 따라 선정한다. 로컬 클라이언트 검증만으로 보안을 보장하지 않는다.
- 기존 디자인 시스템을 우선 사용하고 디자인 채팅의 변경을 보존한다. 독립적인 동시 작업은 격리하고 같은 파일 변경은 조율한다.
- 규칙별 정상·경계·실패 사례를 테스트한다. 불변 조건과 재현 가능한 동기화·재접속 시나리오를 중점 검증한다.

## 단계별 작업

1. **기획 확인과 규칙 모델**: `game-spec.md`의 미결 사항을 확인하고 판·플레이어·행동 및 상태 전이의 초안을 제시한다. 구현을 막는 결정과 임시 가정을 구분한다. 완료: 후속 단계가 참조할 타입·규칙 경계와 미결 목록이 명확하다.
2. **로컬 기본 게임**: 15×15 판, 2인 턴 순서, 유효한 돌 배치, 정확히 5목·6목의 모드별 승리와 무승부, 라운드 흐름을 구현한다. 카드 풀 미정이면 첫 턴을 포함해 턴 시작마다 1장 지급하는 시점만 테스트한다. 완료 기준은 로컬에서 두 모드의 턴·승리·무승부, 목표를 넘는 착수와 잘못된 행동을 검증하는 것이다.
3. **효과 처리 기반**: 확정된 사용 시점·응답 규칙을 반영해 카드 사용, 방어 응답, 효과 지속·만료와 재현 가능한 무작위 처리를 도입한다. 완료: 대상 검증, 효과 순서, 취소·만료 등 대표 시나리오가 테스트된다.
4. **증강·카드 수직 단면**: 기획이 확정된 소수의 대표 효과부터 공격·방어·지속·즉시 보상 흐름을 하나씩 연결한다. 목록 전체를 한 번에 구현하지 않는다. 완료: 획득→사용→방어/효과→만료와 게임 화면이 함께 검증된다.
5. **온라인 2인 플레이**: 방과 참가, 신뢰 가능한 행동 검증, 상태 동기화, 방어 응답, 연결 끊김·재접속, 비공개 정보 전달을 확정한 서비스에 맞게 구현한다. 완료: 두 플레이어의 클라이언트에서 상태 일치, 중복 요청과 재접속을 검증한다.
6. **나머지 콘텐츠와 완성도**: 결정된 카드와 증강을 점진적으로 추가하고 조우자, 밸런스, 접근성·모바일, 배포와 운영을 검증한다. 완료 기준은 기획과 실제 배포 조건에 따라 별도 정의한다.

2단계의 기본 승리·배치와 참가 인원은 [게임 기획](game-spec.md)에 확정했다. 3단계는 방어 타이밍과 효과 순서 결정을, 5단계는 온라인 서비스·신뢰 경계 결정을 기다린다. 디자인과 독립적인 규칙 모델·조사는 병렬로 진행할 수 있다.

온라인 협업은 5단계까지 기다리지 않는다. 1단계부터 통신 조사와 계약 초안을 병행하고, 2단계에는 별도 연결 실험을 한다. 기본 규칙과 세션 계약이 검증되면 기본 착수의 온라인 수직 단면을 연결하고, 카드·방어와 운영 준비는 후속 단계에서 확장한다. 역할과 상세 일정은 [온라인 구현 협업 가이드](online-collaboration.md)를 참고한다.

## 개발 채팅에 전달할 첫 요청

> `docs/game-spec.md`와 `docs/development-roadmap.md`를 읽고 1단계부터 진행해줘. 기존 디자인 채팅의 미커밋 변경을 보존하고 현재 Git 상태를 확인해줘. 게임 규칙과 화면·통신을 분리할 타입 및 상태 전이를 설계하고, 2인 대국과 방어 응답을 고려해줘. 기본 게임 구현을 막는 미결 사항은 임의로 확정하지 말고 질문으로 분리해줘. 작업 결과와 다음 단계를 `docs/work-log.md`에 간단히 기록해줘.

## 후속 단계 요청 방식

해당 단계의 전제 기획이 확정되면 개발 채팅에 “로드맵 N단계를 진행하고, 완료 기준과 관련된 검사를 수행해줘”라고 전달한다. 단계 간 판단이 필요한 사항은 기획 채팅에서 결정하고 `game-spec.md`를 갱신한 뒤 전달한다.
