# 작업 기록

## 현재 상태 — 2026-11-06

- React + TypeScript + Vite 기본 프로젝트와 임시 시작 화면을 구성했다.
- 공통 디자인 토큰, 작업 원칙, 커밋 규칙 및 CI 기본 구성을 추가했다.
- 게임 규칙, 온라인 동기화, 배포 환경은 기획 확인 후 결정한다.
- 검증: `npm run lint`, `npm run build` 통과. GitHub Actions는 첫 푸시 후 확인한다.
- 다음 작업: 게임 기획을 확인하고 규칙과 온라인 연결 방식을 정한다.
- 공유 문서: 기획 채팅에서 확정 사항과 미결 사항을 `docs/game-spec.md`에 정리한다. 디자인 기준과 역할 경계는 `docs/design-system.md`를 참고한다.

## 시작 화면 공통 UI — 2026-11-06

- 시작 화면에 공통 `Button`과 `MenuNavigation`을 적용했다. 색상·간격·포커스·조작 영역은 토큰으로 관리하며, 컴포넌트 사용법은 `docs/design-system.md`에 기록했다.
- 위 UI 코드는 로컬 미커밋 상태이며 아직 GitHub에 반영되지 않았다.
- 검증: `npm run lint`, `npm run build`, `git diff --check` 통과. Chrome의 320·375·1440px 화면에서 메뉴 링크, Tab 포커스 표시, Esc 닫기와 포커스 복귀, 바깥 클릭, 미리보기 버튼과 비활성 예시, 가로 넘침 여부를 확인했다.
- Impeccable의 엔진 컨텍스트 로더는 캐시 쓰기 제한으로 실행하지 못해 기존 문서와 코드로 맥락을 확인했다. 실제 게임 내비게이션은 화면과 이동 흐름이 정해지면 연결한다.

## 기획 및 개발 순서 — 2026-11-06

- 게임 규칙, 증강 10종과 공격·방어 카드 초안을 `docs/game-spec.md`에 기록하고 구현 전 질문을 분리했다.
- 기본 15×15, 2·3인, 라운드 정의, 턴 시작 카드 획득 및 시작 시 별도 지급 없음을 반영했다.
- `docs/development-roadmap.md`에 단계별 선행 조건, 검증 기준과 개발 채팅 전달 문구를 정리했다.
- 남은 작업: 기획의 미결 항목 결정, 개발 채팅에서 1단계 설계. 온라인 서비스와 상세 방어 응답 규칙은 미정이다.

## 1단계 규칙 모델 설계 — 2026-11-06

- [규칙 모델 초안](game-rules-design.md)에 15×15 판, 개인별 승리 조건, 2·3인 턴·라운드 전이와 턴 시작 지급 신호를 정리했다. 화면·통신의 경계, 턴 밖 방어 응답과 비공개 정보 처리 방향도 제시했다.
- 검증은 문서의 TypeScript 예시를 엄격 모드에서 검사하고 `npm run lint`, `npm run build`, `git diff --check`를 실행했다. 모두 통과했다.
- 2단계 착수 전 장목·금수·착수와 턴 종료·판이 가득 찬 경우·선공 기준을 기획에서 확인한다. 카드 풀 결정 전에는 턴 시작 지급 시점만 검증한다.

## 온라인 협업 계획 — 2026-11-06

- [온라인 구현 협업 가이드](online-collaboration.md)에 프로젝트 담당자·온라인 담당자의 역할, WebSocket 계약 초안과 동료 전달 문구를 정리했다.
- 온라인 조사는 지금 병행하고, 2단계에는 독립 연결 실험을 진행한다. 기본 규칙·세션 계약 검증 후 온라인 기본 착수를 연결하며 카드·방어와 운영은 단계적으로 확장한다.
- 서버·호스팅·라이브러리, 인증·재접속 방식과 상세 프로토콜은 미정이다. 실제 온라인 구현이나 동료 전달은 아직 수행하지 않았다.

## 기본 대국 기획 반영 — 2026-11-06

- 5목·6목 모드, 기본 금수 없음, 착수 전 자기 턴 스킬 사용과 착수 후 턴 종료, 빈칸 소진 시 무승부, 첫 경기의 무작위 선공과 재대국 교대를 기획 및 설계 문서에 반영했다. 국제 오목 규칙의 참고 범위를 기록했다.
- 문서의 TypeScript 예시를 엄격 모드로 검사했고, Markdown 로컬 링크와 공백 및 `git diff --check`가 통과했다.
- 남은 기획은 각 모드의 목표를 넘는 줄의 승리 인정 여부와 3인 재대국의 선공 교대 순서다. 2단계는 승리 판정 확정 후 진행한다.

## 기본 승리 조건과 2인 범위 확정 — 2026-11-06

- 두 모드의 승리 조건을 정확히 5목·6목으로 확정했다. 목표보다 긴 줄을 만드는 착수는 유효하다. 로컬·온라인 개발과 검증은 2인으로 정리하고 3인은 확장 후보로 남겼다.
- 검증: 규칙 모델의 TypeScript 예시를 엄격 모드에서 검사했다. Markdown 로컬 링크·공백 검사와 `git diff --check`도 통과했다.
- 다음 단계: 확정된 기획을 바탕으로 2단계 로컬 기본 게임을 구현한다. 카드 풀과 방어 타이밍, 온라인 운영 방식은 후속 단계에서 정한다.

## 2단계 로컬 기본 게임 — 2026-11-06

- 공통 오목판과 모드 선택 컴포넌트에 15×15 로컬 2인 대국을 연결했다. 순수 TypeScript 규칙이 턴·라운드, 정확히 5목·6목, 장목 착수, 무승부를 판정한다. 로컬 세션은 첫 선공을 무작위로 정하고 새 대국에서 선공을 교대한다.
- `npm test`의 규칙·세션 검사 17개, `npm run lint`, `npm run build`, `git diff --check`가 통과했다. 브라우저에서 225개 교차점, 두 모드의 승리와 종료 후 착수 제한, 키보드 착수, 재대국, 좁은 화면에서의 판 확대를 확인했다.
- 카드 풀을 정하기 전에는 턴 시작에 카드 지급 신호만 생성한다. 다음 단계에서 확정된 카드·방어 규칙에 따라 효과 처리와 화면 연결을 추가한다.

## 대국 디자인 시스템 — 2026-11-06

- 공통 오목판, 흑·백돌과 공개 효과 표식, 플레이어 상태, 손패, 상태 알림, 모달과 선택지를 `src/design-system`에 구현했다. 로컬 2인 대국과 별도 **대국 미리보기**에서 공통 판을 사용한다.
- 미리보기에서 5목·6목 설정, 착수·카드 대상 확인, 증강 3택 1, 방어 응답, 승리·무승부, 방 참가·대기·재연결·실패를 살펴볼 수 있다. 카드 21종과 증강 10종은 룰북에서 확인한다.
- 검증: Chrome 320·375·1440px에서 판 크기·넘침·모바일 확대, 방향키 착수, 모달 포커스 복귀와 상태 흐름을 확인했다. 공통 판을 통한 로컬 착수, 린트·빌드·규칙 검사 17개 및 `git diff --check`가 통과했다.
- 사용법과 개발 연동에 필요한 표시 상태·명령은 `docs/design-system.md`에 기록했다. 카드 효과·방어 타이밍·증강 지급·온라인 연결은 확정된 규칙과 세션에서 연동한다. Impeccable 컨텍스트 로더는 캐시 제한으로 실행되지 않아 기획과 코드에서 직접 맥락을 확인했다.
