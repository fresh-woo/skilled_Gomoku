# 온라인 2인 대국 실행과 구현

## 실행

공개 시험 서버: [온라인 대국 열기](https://skilled-gomoku.onrender.com/#online-game). 두 플레이어가 이 주소로 접속해 방 코드를 공유한다. 배포/운영 설정은 [GitHub와 Render 운영 방법](github-and-deployment.md)을 참고한다.

Node.js 24를 사용한다. 같은 저장소에서:

```sh
npm ci
npm run build
npm run server
```

`http://127.0.0.1:8787/#online-game`을 독립된 두 탭/브라우저에서 연다. 첫 화면의 **온라인 방 만들기**를 누르고 표시된 방 코드를 상대에게 전달한다. 상대는 **방 참가**를 누른다. 두 번째 참가 때 게임이 시작된다. 방 생성자가 5목·6목과 기본 대국·스킬 대국 중에서 선택한다. 판 위에서 내 턴과 상대 턴을 확인하고, 방어 응답이 가능하면 손패로 이동할 수 있다.

개발 중에는 별도 터미널에서 `npm run dev`와 `npm run server`를 실행한다. Vite의 `/online` WebSocket 프록시가 같은 서버로 연결한다. 클라이언트에는 고정 서버 주소를 넣지 않는다.

같은 네트워크의 다른 기기에서 접속하려면 빌드 후 PowerShell에서 다음과 같이 바인딩한다:

```powershell
$env:HOST = '0.0.0.0'
npm run server
```

상대는 서버 PC의 LAN 주소 `http://<PC의 LAN IP>:8787/#online-game`으로 접속한다. `127.0.0.1` 주소는 상대 기기에서 사용할 수 없다. 운영체제 방화벽과 Wi-Fi의 기기 간 접근 설정이 연결을 허용해야 한다. 개발 중 LAN 확인은 `npm run dev:lan`과 별도의 기본 서버로도 가능하다. 이번 검증은 한 PC의 독립된 브라우저 두 탭에서 수행했으며 실제 두 기기 간 네트워크 연결은 미검증이다.

인터넷 시험 서비스는 Render 무료 웹 서비스에 배포했다. 같은 Origin에서 화면과 소켓을 제공한다. 다른 실행 환경을 사용하면 Node 서버에 `PORT`, `HOST`를 설정하고 HTTPS 종료와 `/online` WebSocket upgrade 전달을 지원하는 호스트를 사용한다. Render의 공개 Origin은 `RENDER_EXTERNAL_URL`로 허용하며, 별도 도메인은 `ALLOWED_ORIGINS`에 정확한 Origin을 쉼표로 나열한다. 와일드카드 허용과 DB는 추가하지 않았다.

## 동작과 복구 범위

- 게스트 두 자리만 허용하며 방 코드는 참가 권한 역할을 한다. 로그인·전적·관전은 없다. 나가기는 버튼에 표시된 대로 방 전체와 대국을 종료한다. 단순 끊김/새로고침은 나가기로 처리하지 않는다.
- 재접속 토큰은 각 탭의 sessionStorage에 보관해 해당 탭의 새로고침과 일시 끊김을 복구한다. 새 탭/다른 기기로 신원을 옮기는 기능은 제공하지 않는다. 같은 토큰의 새 연결은 이전 소켓을 종료하고 이후 명령을 차단한다. 로그에 토큰을 출력하지 않는다.
- 서버 heartbeat는 15초 주기로 끊긴 연결을 감지한다. 클라이언트는 상한 5초와 jitter를 가진 백오프로 재연결한다. 스냅샷 수신 전/상대 턴/방어 응답 대기 중에는 허용되지 않은 조작을 막고 서버가 다시 검증한다.
- 양쪽 모두 끊긴 방은 마지막 연결 종료 후 10분 동안 메모리에 유지한다. 한 명이 남아 있으면 대기한다. 정식 스킬 대국의 저격 방어는 연결이 끊겨도 15초 마감을 유지한다. 마감 전 재접속하면 같은 응답 창을, 마감 후에는 확정된 결과를 받는다.
- 서버 재시작 시 모든 방·토큰·진행 상태가 사라진다. 여러 서버 인스턴스 간 공유는 지원하지 않는다. 방 100개, 메시지 4KiB, 소켓당 초당 30개 제한과 Origin 검사만 갖춘 소규모 게스트 버전이다. 공개 서비스의 계정·영속 복구·인프라 단위 악용 방지는 후속 범위다.
- 두 명이 승리/무승부 후 모두 **재대국 준비**를 눌러야 새 게임이 시작된다. 모드와 규칙은 유지하고 선공은 이전 후공으로 바뀐다. 중도 재시작은 새 방을 만든다.

## 규칙과 서버 경계

`server/index.mjs`는 Node 24의 TypeScript 지원으로 `game.ts`의 `startGame/applyCommand`, `skillGame.ts`의 `startSkillGame/applySkillCommand`를 호출한다. 온라인 스킬 대국은 매 턴 시작에 네 카드 중 한 장을 같은 확률로 지급한다. 무장해제는 방어자가 적용 전에 응답하거나 건너뛸 때까지 기다린다. 무효화로 저격과 무장해제를 막으면 무효화 카드만 소모한다.

서버는 세션에서 행동자를 정하고 허용된 action 필드만 추출한다. 클라이언트가 보낸 actorId·대상 신원·완성 판은 사용하지 않는다. 플레이어별 스냅샷에는 공개 game, 본인 손패, 양쪽의 손패 수, 방어 대상·마감·결과와 보호막이 포함된다. 상대 손패와 버린 카드 상세·덱·난수·예약 효과는 직렬화하지 않는다. 이후 지뢰·은신 등 비공개 판 상태를 도입할 때는 이 공개 game 투영도 확장해야 한다.

## 실제 메시지

승인된 착수와 카드 사용에는 별도 `sound` 메시지(`gameId`, `revision`, `cues`)를 현재 연결된 두 플레이어에게 보낸다. 공개 효과 종류만 담고 카드 ID나 손패는 보내지 않는다. 거부·중복 요청에서는 재발행하지 않고 스냅샷에도 넣지 않는다. 클라이언트는 참가/재접속의 첫 스냅샷으로 기준 revision을 잡아 이전 소리와 동일 이벤트를 다시 재생하지 않는다. 오디오 전달은 상태 저장·복구와 독립적이다.

모든 요청은 `v:1`, `requestId`를 포함한다. `src/features/online-game/protocol.ts`가 화면에 전달할 타입을 정의하며 서버는 런타임에서 메시지를 검증한다. 이전 `experiments/websocket/contracts.ts`는 과거 설계 실험이며 실제 API가 아니다.

| 요청 | 필드 | 응답 |
| --- | --- | --- |
| create | mode, rules (`basic` 또는 `skills`) | session, snapshot |
| join | roomId | session, snapshot 또는 ROOM_NOT_FOUND/ROOM_FULL |
| resume | token | session, 최신 snapshot 또는 SESSION_EXPIRED |
| sync | 없음 | 본인 snapshot |
| command | gameId, revision, action | result와 각자의 snapshot |
| leave | 없음 | 방 종료, 두 소켓 close(4003) |

action은 `place-stone(position)`, `use-skill(cardId, position?)`, `respond(attackId, cardId?)`, `choose-augment(augmentId, round)`, `rematch`다. 각 방은 동기적으로 공통 규칙을 호출한다. 승인된 게임 전이와 서버의 방어 마감 처리, 새 대국에서 revision이 증가한다. `(플레이어, requestId)`의 입력과 결과를 보관해 동일 입력의 재전송에는 같은 결과를 반환한다. 다른 입력의 ID 재사용과 오래된 gameId를 거부한다. 이전 revision의 증강 선택은 같은 라운드의 선택이 열려 있을 때만 받아들인다. 대국당 자리별 2048개 결과까지 보관하며 한도를 넘으면 추가 명령을 거부한다. 재대국 시 게임 ID와 기록을 갱신한다.

클라이언트는 한 번에 한 명령만 보내고 응답 전 끊기면 재접속 스냅샷 수신 후 같은 ID로 재전송한다. 새로고침에서는 미응답 명령을 새 ID로 다시 실행하지 않고 서버 스냅샷으로 확정된 결과를 확인한다. 승인된 상태 전이만 카드 지급을 수행하며 복구는 규칙 초기화를 호출하지 않는다.

## 검증

`npm test`에서 5목·6목 승리·재대국, 신원 위조 거부, 중복·변조·오래된 요청, 방 정원과 Origin 검사, 상대 손패 비공개, 방어 후 원래 턴 재개와 재접속을 검증한다. 정식 스킬 대국의 통합 테스트는 잘못된 대상, 무효화 비용, 중복 응답과 접속이 끊긴 상태의 15초 마감을 확인한다.

브라우저 두 탭에서 방 생성/참가, 양쪽 착수와 턴 동기화, 새로고침 후 동일 자리·돌 복구를 확인했다. 스킬의 화면 조작은 기존 컴포넌트를 재사용하며 서버 스킬/방어 흐름은 통합 테스트로 확인했다. 모바일 두 기기, 실제 인터넷 지연·패킷 손실, 장시간 부하·다중 인스턴스는 검증하지 않았다.
